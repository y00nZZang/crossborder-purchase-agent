# 설계와 한계

## 브라우저 판단과 결정적 처리의 분리

상품 탐색·폼 의미 해석은 Codex skill이 맡는다. Python helper는 승인한 조건의 digest, 시도 기록, 상태 전이, 견적 산술을 검증한다. 브라우저가 버튼을 눌렀다는 사실과 실제 주문·신청이 접수됐다는 사실은 구분한다. 외부 사이트와 SQLite 사이에 분산 트랜잭션이 있는 것은 아니다.

## 중복 방지

실행 intent와 승인 조건을 대조하고 상태를 저장한다. 결과가 불명확할 때 새 주문을 반복하지 않고 기존 주문·접수 목록을 먼저 확인한다. 이 방어는 helper를 사용한 경로에 적용되며, 사람이 별도로 누른 버튼이나 에이전트가 생략한 기록을 완전히 통제하지 않는다.

## 실험에서 드러난 공백

1. 무게만 있는 EMS 견적에도 치수를 요구하여 계산을 진행하지 못했다. 운송 방식별 필수 입력 계약 분리가 필요하다.
2. 몰테일 USD 요금의 환산을 지원하지 않아 원통화를 유지했다.
3. 사용자 직접 주문을 ledger에 가져오는 명령이 없어 별도 비공개 기록으로 실제 결과를 대조했다.
4. 주문 확인 화면과 주문 상세에 3엔 차이가 있었다. 실제 접수 금액을 기준으로 등록했으며 차이의 원인은 확인하지 못했다.

이 문제를 숨기거나 임의 값으로 통과시키지 않았다. 현재 공개 코드는 실험 당시 동작을 보존한다. 향후 개선 순서는 외부 주문 import와 근거 검증, 운송 방식별 입력, USD 환산, 배송 추적 실검증이다.

## URL 분석기와의 관계

[Product Catalog](https://github.com/y00nZZang/product-catalog)는 URL 기반 상품 수집·포장·배송·관세 추정 서버다. 두 프로젝트는 공통 문제를 다루지만 현재 자동 API 연동된 하나의 구매 시스템은 아니다. 이 저장소는 계정과 실제 거래를 다루는 실행 보조에 집중한다.
