# 구매 확인 후 일일 추적 — plugin 0.1.1

2026-10-06 변경. 구매 접수가 확인되면 배송대행 신청 완료를 기다리지 않고 Codex heartbeat에 하루 한 번의 메일 확인 작업을 등록하는 기본 후속 절차를 연결했다. 사용자 단발 실행·반복 추적 제외 요청은 우선한다.

1. 실제 주문을 실행 기록에 연결하고 메일 단회 조회 성공을 확인한다.
2. `schedule-plan RUN`으로 구매 확인 트리거·일일 주기·프롬프트를 얻는다. helper 자체는 예약 서비스가 아니다.
3. Codex 환경의 예약 도구로 생성/갱신한다. 시간·시간대 지정이 있으면 사용하고 없으면 등록 시각 기준으로 매일 확인한다.
4. 반환된 ID를 `attach-schedule`로 기록한다. 기존 예약이 있으면 중복 생성하지 않는다.
5. 배송대행 신청 전에는 주문부터 추적하고, 신청 후 같은 예약에서 발송·입고·운임·출고·통관·배송을 대조한다.
6. 변경·조회 실패·사용자 행동 필요 시 알리고, 변화가 없으면 조용히 유지한다. 배송완료·취소 시 예약 종료 결과를 확인한다.

구매·배송비 납부·취소·통관 신고를 예약 작업이 임의로 수행하지 않는다. 메일/예약 도구와 계정 연결이 필요하다. 사용자 직접 주문이 helper에 연결되지 못하는 기존 공백은 남아 있으므로 가짜 구매 시도로 우회하지 않는다.

검증: helper 테스트28개 통과, skill 형식 검사5개 통과. 추가한 테스트는 주문 확정 전 등록 거절, 배송대행 신청 전 등록 계획, 배송대행 확정 후 같은 예약 재사용, 취소 주문 등록 거절을 확인한다. 실제 예약 장기 실행은 검증하지 않았다.10/5 실구매와 사용자 입력7회는0.1.0의 과거 관측이다.

배포 소스와 ZIP은0.1.1이다. 이미 설치된0.1.0 캐시는 이 저장소 변경만으로 갱신되지 않으므로 Codex에서 로컬 플러그인을 업데이트/재설치한 뒤 사용해야 한다. 이번 문서 편집 작업은 실제 주문을 추적하는 새 예약을 만들지 않았다.
