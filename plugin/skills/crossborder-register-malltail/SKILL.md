# 몰테일 배송대행 등록

[몰테일 필드 지도](../../references/malltail.md), [실행 규칙](../../references/execution.md), [런타임](../../references/runtime.md)을 읽는다. 구매대행이 아닌 배송대행이다. 주문 확인된 run이 선행되어야 한다.

1. 몰테일 기존 신청내역을 원주문번호와 대조한다. 같은 주문 접수가 있으면 재제출하지 않고 그 신청을 확인하여 연결한다. 임시 URL과 접수된 신청은 다르다. 기존 접수 연결은 `begin forwarding` 후 외부 쓰기 없이 확인 근거로 resolve한다.
2. 사용자가 승인한 배송신청 범위가 있는지 확인한다. 로그인된 페이지에서 필요한 입력을 근거별로 작성한다. 이름·주소·통관번호는 승인된 사이트 저장 프로필을 우선 사용한다. 개인 정보를 새로 전송해야 하면 그 정보와 목적지에 대한 권한을 확인한다.
3. 센터·원주문번호·상품명·옵션·수량·통화·실제 상품액·품목을 대조한다. 미관측 소분류·3/4단계는 현재 화면을 조사하여 해결하고, 알 수 없는 필수값을 추정하지 않는다. 이미지 없음은 검수 조건에 영향을 줄 수 있으므로 현재 옵션을 설명한다.
4. 상품·수령정보·추가 옵션·비용 요약을 검토한 후 `begin forwarding`. 실제 제출 후 접수번호와 저장된 내역을 확인하여 `resolve confirmed`. 불명확하면 unknown으로 기록하고 목록을 조회한다.
5. 발송 전 운송장이 없으면 허위 값으로 채우지 않는다. 나중에 판매점 발송 근거를 원주문과 대조하고 해당 신청에만 추가한다. 승인에 allow_tracking_update가 있고 새 운송장이 기존 값과 다를 때 `begin tracking_update`, 저장 후 재조회하여 resolve한다. 이미 저장된 값이면 변경 없이 확인한다.
6. 입고 후 실측 운임/검수 결과를 기록하고 배송비 결제는 첫 버전에서 사용자에게 인계한다. 신청 접수만으로 출고 완료라고 보고하지 않는다.

완료 보고에는 접수 확인 여부·누락값·다음 이벤트를 포함하되 비공개 식별자 원문은 공개 자료에 넣지 않는다.
