# 배송 추적과 반복 작업

[런타임 계약](../../references/runtime.md)과 [추적 운영](../../references/tracking.md)을 읽는다. 특정 run의 주문/신청번호를 비공개 상태에서 찾아 Gmail과 사이트를 조회한다. 도구가 없거나 인증이 만료되면 마지막 성공 시각과 필요한 조치를 보고한다. 배송 지연으로 단정하지 않는다.

원주문 식별자와 사건 시각을 확인한 메시지만 연결한다. 취소된 과거 주문이나 상품명이 같은 다른 주문은 제외한다. 메일 수신시각과 사건 발생시각을 구분한다. `observe`는 동일 이벤트 ID를 중복 반영하지 않고 늦게 도착한 과거 이벤트가 단계를 후퇴시키지 않는다. 취소는 일반 배송단계가 아니라 `cancel`로 근거와 함께 기록한다. 환불 및 몰테일 신청 취소를 판매점 취소로 추정하지 않는다.

배송 완료까지 신규 운송장·입고·비용·출고·통관 요청·배송완료를 확인한다. 새 운송장 등록은 별도 쓰기 작업이므로 여기서는 알리고 register-malltail로 넘긴다. 신규 구매·취소·납부·신고는 하지 않는다. 배송완료 표시는 delivered, 사용자의 실물 확인은 received다.

반복 요청이 있으면 먼저 단회 조회 성공을 확인한다. `schedule-plan RUN`을 통해 지침을 만들고 현재 환경의 공식 예약 작업 도구로 이 채팅의 반복 작업을 생성/갱신한다. 처음은 하루 한 번, 사용자 지정 시간·시간대를 사용한다. 시간을 모르면 질문한다. 기존 automation_ref가 있으면 새로 만들지 않는다. 도구가 반환한 ID를 `attach-schedule`로 저장하고 도구 결과로 등록 성공을 확인한다. 지침 파일 생성만으로 예약이 등록됐다고 말하지 않는다.

변화가 없으면 알리지 않는다. 의미 있는 상태 변경·조회 실패·사용자 행동 필요 시만 통지한다. 취소/배송완료 시 실제 예약 작업을 종료하고 결과를 확인한다. 수령 확인은 마지막 브리핑에서 사용자에게 요청하며 사용자가 별도 추적을 원하면 따른다. 자동 중단 도구가 실패하면 그 실패를 명시한다.
