# 추적 운영

현재 사용 가능한 Gmail read/search와 브라우저 도구를 사용한다. 메일 본문 전체를 DB에 복사하지 않고 사건 종류·시각·근거 참조만 기록한다. 발신자와 주문번호/상품을 대조한다. 사이트와 충돌하면 최신이라고 덮어쓰지 말고 원주문의 상세 상태를 확인한다. 조회마다 `record-check`로 성공 시각/실패 여부를 비공개 상태에 남기고 미조회 기간을 브리핑에 표시한다.

상태: ordered → seller_shipped → warehouse_received → shipping_quoted → shipping_paid → international_shipped → customs → delivered → received. 여러 단계를 건너뛴 실제 근거도 기록할 수 있다. 뒤늦은 과거 메일은 이력에만 추가한다. 반송·파손·보완 요청은 이 선형 단계로 억지 변환하지 않고 사용자 조치로 알린다.

반복 도구에서 현재 채팅의 heartbeat를 우선한다. 로컬 파일/브라우저를 쓰는 환경인지 확인하고 한 번 실제 조회해 본다. 컴퓨터·앱 종료나 로그인 만료에 대응하는 원격 상시 서비스가 구현된 것은 아니다. 구매 확인 직후 하루 한 번의 추적을 등록하고 결과 ID를 저장한다. 지정된 시간·시간대가 있으면 적용하며, 없으면 등록 시각 기준 일일 주기를 사용한다. 배송대행 신청 전에는 주문부터 추적하고 신청 후 같은 예약에 배송대행 상태를 연결한다. 멱등 키는 run ID이며 기존 작업이 있으면 갱신한다.

변화 없으면 조용히 유지. 조회 실패가 계속될 때 동일 알림 반복 대신 원인과 마지막 성공시각을 알리고 사용자 복구를 기다린다. 결제·통관 요청 메일의 링크를 곧바로 실행하지 말고 공식 사이트에서 동일 요청을 확인한다.

배송완료/취소가 확인되면 예약 작업을 실제 종료하고 그 결과를 기록한다. 도구 API는 실행 환경의 문서를 따른다. schedule-plan은 프롬프트 초안일 뿐 등록 명령이 아니다. 배송완료 후 수령/파손 확인은 사용자가 제공한 사실로만 기록한다.
